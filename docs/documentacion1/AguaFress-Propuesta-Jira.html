📋 AguaFress — Propuesta de Organización en Jira

3 opciones para estructurar el proyecto

Contexto

5 devs, 4 meses de desarrollo + 1 mes de colchón, 6 microservicios + gateway + frontend. La organización en Jira debe permitir trackear progreso sin generar overhead administrativo.

Opción A — Epic por mes (recomendada)

RECOMENDADA

Una Epic por cada mes de desarrollo

EpicMesContenido
AG-MES-1Mes 1Base: proyectos NestJS, Prisma schemas, migrations, Docker, health checks
AG-MES-2Mes 2Eventos: Redis Streams, integración entre servicios, contratos
AG-MES-3Mes 3Frontend: vistas principales, conexión con Gateway
AG-MES-4Mes 4Cierre: tests, bugs, documentación, deploy

✅ Ventajas: Simple, clara, alineada al cronograma. Cada mes tiene un objetivo medible.

❌ Desventajas: Mezcla servicios en la misma epic. Difícil ver el progreso individual.

Opción C — Híbrido (epics por mes + stories por dev)

Epics por mes, stories asignadas a cada dev

Es la combinación de las dos anteriores:

  • 4 epics (una por mes) como la Opción A
  • Dentro de cada epic, stories asignadas a cada dev
  • Cada story tiene acceptance criteria y depende de otras stories

Ejemplo: Mes 1 (AG-MES-1)

StoryDevDescripciónDepende de

✅ Ventajas: Lo mejor de ambos mundos. Visibilidad mensual + responsabilidad individual. Las dependencias son explícitas.

❌ Desventajas: Requiere más planificación inicial. Más stories que mantener.

Recomendación final

✅ Opción C — Híbrido. Epics por mes para visión general, stories por dev para responsabilidad individual. Es la que mejor escala para equipos que están aprendiendo.

Cómo seguir

  1. Elegir una opción en equipo (discutir en la daily)
  2. Crear las epics en Jira
  3. Generar las stories del Mes 1 con acceptance criteria
  4. Asignar a cada dev y arrancar
