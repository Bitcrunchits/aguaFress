Plataforma de Pedidos y Gestión para Distribuidores de Agua y Soda

Proyecto Full Stack - Grupo de Desarrollo

1. Descripción del Proyecto

aguaFress es una plataforma web (MVP) diseñada para conectar vendedores independientes de agua y soda con sus consumidores. El problema que resuelve: los consumidores deben esperar la visita semanal del vendedor para reponer producto, y los vendedores realizan visitas improductivas a clientes que no necesitan mercadería.

La solución permite al consumidor solicitar pedidos en cualquier momento (fuera del día de ruta habitual) y confirmar/.cancelar la visita programada, optimizando la logística del vendedor y aumentando las ventas por pedidos adicionales.

2. Propuesta de Valor - Diferencia Competitiva

¿Qué nos diferencia de las apps existentes en Argentina?

  • Pedido directo del consumidor: Ninguna app en Argentina permite al cliente final pedir directamente al distribuidor desde su propia app/web.
  • Confirmación de visita: Sistema único que evita visitas improductivas - el consumidor confirma o cancela antes de que el vendedor salga de ruta.
  • Pedidos fuera de día de ruta: El cliente puede pedir en cualquier momento, no solo en la visita programada.
  • Ruta inteligente: Generación automática de rutas diarias basadas en pedidos confirmados con navegación GPS integrada.
  • Marketplace vs Software interno: Todas las apps actuales son sistemas de gestión internos (Gestión Aguas, JR-Agua, App Delivery Agua). aguaFress es un marketplace bidireccional.

4. Análisis de Tecnologías y Estrategia de Desarrollo

📦 Estrategia de Desarrollo: Desarrollo local con Docker → Migración a cloud en producción

Backend

NestJS - Framework TypeScript progresivo, arquitectura modular, integración nativa con TypeORM y GraphQL, ideal para aplicaciones escalables.

✓ Recomendado

Base de Datos - REQUISITO DEL PROFESOR

Motor Uso en el Proyecto
PostgreSQL Datos principales: Usuarios, Pedidos, Productos, Facturación, Rutas
MySQL Logs de auditoría, analytics histórico, reporting (consultas OLAP)
MongoDB Notificaciones push, mensajes chat, caché de sesiones, logs de actividad

Justificación técnica: Cada DB tiene propósito específico. PostgreSQL para datos transaccionales ACID, MySQL para analytics/reporting (compatible con herramientas como Metabase), MongoDB para datos NoSQL como mensajes y notificaciones.

Frontend Web (V1.0)

React + TypeScript - Componentes reutilizables, ecosistema maduro, integración con NestJS vía REST/GraphQL.

✓ Recomendado

App Móvil (V2.0)

Opción Veredicto
React Native ✓ Recomendado
Ionic ✗ Para apps simples

Justificación: Para V2.0 con AI, mapas, UI compleja y rendimiento nativo, React Native es superior. Ionic usa WebView, menor rendimiento. Compartimos conocimiento React entre web y mobile.

9. Por qué esta arquitectura es ideal para el proyecto

  • Docker Compose: Todos los servicios levantan con un solo comando docker compose up
  • Triple DB obligatoria: PostgreSQL (core), MySQL (analytics), MongoDB (logs/chat)
  • Arquitectura multi-database: NestJS puede conectar a múltiples DBs con TypeORM/Prisma
  • Separación clara: Cada DB tiene propósito específico y aislamiento
  • Escalable: De Docker local a cloud gestionado sin refactorizar
  • Testing: Mailhog para testear emails sin enviar realmente

10. Arquitectura Multi-Database en NestJS

El proyecto usará múltiples conexiones de base de datos en un mismo Backend NestJS:

Módulo NestJS Base de Datos ORM Entidades
Auth Module PostgreSQL TypeORM Users, Roles, Tokens
Products Module PostgreSQL TypeORM Products, Categories, Images
Orders Module PostgreSQL TypeORM Orders, OrderItems, Payments
Analytics Module MySQL TypeORM SalesHistory, Reports, Metrics
Notifications Module MongoDB Mongoose Messages, PushNotifications, ActivityLogs

Implementación: Cada módulo de NestJS tendrá su propia conexión a la base de datos correspondiente, permitiendo separación clara de responsabilidades.
