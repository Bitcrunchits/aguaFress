Git + GitHub + Trabajo en equipo

Flujo profesional, commits limpios y colaboración efectiva

Resumen completo del flujo de trabajo en equipo usando Git y GitHub: ramas, Pull Requests, revisión de código y convención de commits (Conventional Commits) para mantener proyectos ordenados y trazables.

1

Flujo de trabajo en equipo

De la clonación del repositorio al merge en main, pasando por ramas de feature y Pull Requests.

[1] git clone
⟶
[2] Crear rama
feature/nombre-feature
⟶
[3] Desarrollar
código + tests
⟶
[4] git add +
git commit
⟶
[5] git push origin
feature/...
⟶
[6] Pull Request
⟶
[7] Review
⟶
[8] Merge a main
Ejemplo práctico de comandos
git clone https://github.com/empresa/proyecto.git
cd proyecto
git checkout -b feature/login-jwt
# (desarrollo)
git add .
git commit -m "feat(auth): agregar login con JWT"
git push origin feature/login-jwt
# Crear Pull Request hacia main en GitHub
2

Reglas del equipo

Convenciones mínimas para mantener el repositorio limpio y colaborativo.

  • Protección de main: nadie trabaja directo sobre main. Todo pasa por ramas + PR.
  • Ramas por tarea: una rama por Issue/tarea, con nombres descriptivos.
  • Commits atómicos: un cambio lógico por commit.
  • Review obligatorio: todo cambio se integra vía Pull Request revisado por otra persona.
  • Issues vinculados: cada PR referencia su Issue (Closes #id) para trazabilidad.
Ejemplos de nombres de ramas
feature/login-jwt
feature/filtrado-productos
fix/timeout-lista-usuarios
refactor/estructura-servicios-api
3

Convención de commits

Uso de Conventional Commits para mensajes claros, automatizables y fáciles de leer.

Formato básico 
tipo(scope): descripción corta
Tipos comunes

feat → nueva funcionalidad

fix → corrección de bug

docs → solo documentación

style → formato/estilo sin lógica

refactor → cambio interno sin nuevo comportamiento

test → tests

chore → mantenimiento/configuración

Scope (zona afectada)

auth → autenticación/autorización

users → gestión de usuarios

ui → interfaz de usuario

api → endpoints y servicios

database → modelos/migraciones

config → configuración/env vars

Ejemplos
feat(users): crear endpoint de registro
fix(auth): corregir validación de token
refactor(api): mejorar estructura de servicios
docs(readme): documentar setup del proyecto

Ejemplos y Breaking Changes

Mensajes de commit bien construidos y cómo marcar cambios que rompen compatibilidad.

feat
feat(users): crear endpoint de usuarios
feat(api): implementar paginación en lista
feat(ui): añadir componente de búsqueda
fix
fix(auth): corregir validación de token
fix(api): solucionar error de timeout
fix(ui): arreglar estilo responsive
refactor
refactor(api): mejorar estructura de servicios
refactor(users): simplificar lógica de validación
refactor(database): optimizar consultas
