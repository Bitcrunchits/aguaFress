🔗 Flujo QR / Link — Invitación de Vendedor

1. Admin activa vendedor → status: pendiente → activo 2. Vendedor genera QR y link público (/vendedor/qr, /vendedor/link) 3. Vendedor comparte QR/link con sus clientes 4. Cliente abre link → ve formulario de registro 5. Se registra → auth-service crea USER con role=cliente 6. User-service escucha UserCreated + token QR → crea CLIENTE + RELACION_CARTERA 7. Cliente ya está en la cartera del vendedor 🎯

🔐 1. Auth Service Lucas

Puerto 3001 · PostgreSQL · Prisma

Tablas

USER (id, email, password_hash, role, created_at, updated_at, deleted_at)
SESSION (id, user_id, token, expires_at)
REFRESH_TOKEN (id, user_id, token, expires_at)

Endpoints

POST /auth/login — email+password → JWT POST /auth/register — admin crea usuario (clientes) POST /auth/register-vendedor — público, queda pendiente POST /auth/google — Google OAuth → JWT POST /auth/refresh — refresh token → nuevo JWT POST /auth/logout — invalida token

Eventos que publica

UserCreated { userId, email, role, timestamp }

👤 2. User Service Lucas

Puerto 3002 · PostgreSQL · Prisma

Tablas

VENDEDOR · CLIENTE · RELACION_CARTERA · DIRECCION · CIUDAD · BARRIO
RUTA · QR_CODE · LINK_INVITACION · EXPORT_DATA

Endpoints principales

GET /users/me — mi perfil PATCH /users/me — actualizar mi perfil GET /users — admin lista todos PATCH /users/:id/asignar-vendedor — admin asigna cliente a vendedor GET /users/mis-clientes — vendedor ve su cartera GET /users/mi-vendedor — cliente ve su vendedor POST /vendedor/qr — vendedor genera QR POST /vendedor/link — vendedor genera link público GET /public/vendedor/:qrToken — perfil público vía QR + CRUD admin (listar, ver, actualizar, baja lógica, activar/desactivar)

Escucha

UserCreated (de auth) → crea perfil VENDEDOR o CLIENTE

Eventos que publica

VendedorStatusChanged { vendedorId, estado, timestamp }
CarteraClienteAdded { vendedorId, clienteId, timestamp }

📦 3. Products Service Emiliano

Puerto 3003 · PostgreSQL · Prisma

Tablas

PRODUCTO (vendedor_id, sku, nombre, descripcion, marca_id, categoria_id, precio_sin_iva, precio_final, stock, stock_minimo, activo, mostrar_precio)
MARCA · CATEGORIA · PRODUCTO_IMAGEN · DESCUENTO (modelo, sin feature activa)

Endpoints

GET /products?vendedorId&categoria — catálogo con filtros GET /products/:id — detalle producto POST /products — vendedor crea producto PATCH /products/:id — vendedor actualiza DELETE /products/:id — vendedor elimina (baja lógica) GET /products/search?q&vendedorId — búsqueda

Eventos que publica

ProductUpdated { productId, vendedorId, timestamp }
ProductDeleted { productId, vendedorId, timestamp }

🛒 4. Orders Service Adrián

Puerto 3004 · PostgreSQL · Prisma

Tablas

CART (usuario_id, vendedor_id, expires_at)
CART_ITEM (cart_id, producto_id, cantidad, precio_unitario)
ORDER (pedido_numero, usuario_id, vendedor_id, direccion_entrega_id, estado, metodo_pago, total_sin_iva, iva, total, observaciones)
ORDER_ITEM · ORDER_HISTORY · FACTURA

Endpoints — Carrito

GET /cart?userId — ver carrito activo POST /cart/items — agregar producto PATCH /cart/items/:id — modificar cantidad DELETE /cart/items/:id — quitar producto

Endpoints — Pedidos

GET /orders?userId&vendedorId — listar pedidos GET /orders/:id — detalle pedido POST /orders — crear pedido desde carrito PATCH /orders/:id/status — cambiar estado POST /orders/:id/confirmar — cliente confirma visita POST /orders/:id/cancelar — cancelar pedido

Reglas de negocio

  • Carrito expira a las 24hs (estado vencido)
  • Método de pago: solo contra_entrega en MVP
  • Estados: pendiente → confirmado → en_camino → entregado / cancelado / vencido
  • Factura: el vendedor sube imagen (PDF/JPG)

Eventos que publica

OrderCreated { orderId, vendedorId, clienteId, total, timestamp }
OrderStatusChanged { orderId, estado, timestamp }

🚚 5. Entregas Service Milagros NUEVO

Puerto 3005 · PostgreSQL · Prisma

Tabla

ENTREGA (id, order_id, vendedor_id, estado, direccion_entrega [JSON], fecha_asignacion, fecha_entrega, notas)

Endpoints

GET /deliveries?fecha=HOY — vendedor ve entregas del día GET /deliveries/:id — detalle de una entrega PATCH /deliveries/:id/status — cambiar estado (en_camino | entregada)

Reglas de negocio

  • Vendedor = repartidor (misma persona en MVP)
  • Sin mapa GPS interactivo en MVP (feature futuro)

Escucha

OrderConfirmed (de orders) → crea ENTREGA con estado pendiente

Eventos que publica

DeliveryStarted { deliveryId, orderId, timestamp }
DeliveryCompleted { deliveryId, orderId, timestamp }
